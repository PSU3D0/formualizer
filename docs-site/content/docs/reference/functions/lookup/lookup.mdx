Searches for a value and returns a corresponding value from another range.

`LOOKUP` always performs approximate matching: it returns the largest value
 less than or equal to the lookup value, found with Excel's binary search.

The Formualizer engine in this repository at 0.16.0 plus unreleased changes computes the example results. Known differences from Excel are listed on this page.

## Syntax

`=LOOKUP(lookup_value, lookup_vector_or_array, [result_vector])`

## Arguments

| Argument | Type | Required | Default |
| --- | --- | --- | --- |
| `lookup_value` | any | Required | — |
| `lookup_vector_or_array` | any (range) | Required | — |
| `result_vector` | any (range) | Optional | — |

## Remarks
 - **Vector form** `LOOKUP(value, lookup_vec, result_vec)`: searches `lookup_vec`,
   returns the element at the same position of `result_vec`.
 - **Array form** `LOOKUP(value, array)`: if width &gt; height searches first row
   and returns from last row; otherwise searches first column and returns from
   last column. A 2-D lookup vector in the vector form is searched the same way.
 - The sort order is never checked. On sorted data the answer is the largest
   value not above the lookup value; on unsorted data it is wherever Excel's
   search leads (lower midpoint, end of the run of equal values it first
   hits), and formualizer gives the same answer: `LOOKUP(1,{1,1,1,1,1,0,1})`
   is the 5th value.
 - Errors, blank cells and values of another type than the lookup value are
   stepped over, never compared: `=LOOKUP(2,1/(A1:E1&lt;&gt;""),A1:E1)` returns the
   last non-blank value of the row. A number never matches numeric text or a
   boolean (`LOOKUP(2,{1,"2",3})` is 1), texts compare as texts ignoring
   case, and numbers compare exactly. A blank lookup value is 0.
 - A whole-column reference is searched over all its rows, as in Excel,
   which matters on unsorted data only.
 - A result array that is too short, and a 2-D result, give `#N/A`.

## Error cases

 - Returns `#N/A` when no value of the lookup value's type is less than or
   equal to it, and the lookup value itself when it is an error.

## Examples

<FunctionExample
  title={"Look up a value between two keys and return the corresponding label."}
  formula={"=LOOKUP(25,{10,20,30},{\"Low\",\"Mid\",\"High\"})"}
  grid={{}}
  expected={"Mid"}
/>

<FunctionExample
  title={"Use the array form with keys in the first row."}
  formula={"=LOOKUP(25,{10,20,30;100,200,300})"}
  grid={{}}
  expected={"200"}
/>

<FunctionExample
  title={"A key equal to the smallest lookup entry has a match."}
  formula={"=LOOKUP(10,{10,20,30},{\"Low\",\"Mid\",\"High\"})"}
  grid={{}}
  expected={"Low"}
/>

<FunctionExample
  title={"A lookup smaller than the first key cannot be paired with a result."}
  formula={"=LOOKUP(5,{10,20,30},{\"Low\",\"Mid\",\"High\"})"}
  grid={{}}
  expected={"#N/A"}
/>

<FunctionExample
  title={"Vector form exact hit"}
  formula={"=LOOKUP(2,A1:A3,B1:B3)"}
  grid={{"A1":"1","A2":"2","A3":"3","B1":"\"a\"","B2":"\"b\"","B3":"\"c\""}}
  expected={"b"}
/>

<FunctionExample
  title={"Vector form approximate"}
  formula={"=LOOKUP(3.5,A1:A5)"}

/>

## FAQ

### Does LOOKUP support exact matching?
No. LOOKUP always performs approximate matching (largest &lt;= lookup value).

### What happens with unsorted data?
LOOKUP never checks the sort order and returns the position Excel's binary search reaches, as Excel does. Unlike MATCH and VLOOKUP, which return #N/A on unsorted data, it never refuses to search.

### How does LOOKUP treat errors and other types in the lookup vector?
It steps over them: only values of the lookup value's type are compared. That is why =LOOKUP(2,1/(A1:E1&lt;&gt;""),A1:E1) returns the last non-blank value: the blanks become #DIV/0! errors and 2 is larger than every 1.

Finds text within text using non-DBCS byte-compatible semantics.

In Formualizer's invariant locale, FINDB delegates to FIND and counts Unicode
 scalar characters rather than double-byte locale bytes.

The Formualizer engine in this repository at 0.15.0 plus unreleased changes computes the example results. Known differences from Excel are listed on this page.

## Syntax

`=FINDB(find_text, within_text, [start_num])`

## Arguments

| Argument | Type | Required | Default |
| --- | --- | --- | --- |
| `find_text` | any | Required | — |
| `within_text` | any | Required | — |
| `start_num` | any | Optional | — |

## How it works

Delegates to FIND in Formualizer’s invariant locale. It returns 1 plus the number of Unicode scalar characters before the case-sensitive match. An out-of-range start or absent match returns an error.

## FAQ

### Does FINDB use DBCS byte counts?
Not currently. In the invariant locale it delegates to FIND.

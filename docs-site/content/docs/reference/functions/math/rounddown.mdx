Rounds a number toward zero to a specified number of digits.

The Formualizer engine in this repository at 0.15.0 plus unreleased changes computes the example results. Known differences from Excel are listed on this page.

## Syntax

`=ROUNDDOWN(number, num_digits)`

## Arguments

| Argument | Type | Required | Default |
| --- | --- | --- | --- |
| `number` | number | Required | — |
| `num_digits` | number | Required | — |

## Remarks
 - Positive `num_digits` affects decimals; negative values affect digits left of the decimal.
 - Always reduces magnitude toward zero (unlike `INT` for negatives).
 - Input errors are propagated.

## Examples

<FunctionExample
  title={"Round to two places to the right of the decimal point."}
  formula={"=ROUNDDOWN(12.345,2)"}
  grid={{}}
  expected={"12.34"}
/>

<FunctionExample
  title={"Round to a place left of the decimal point."}
  formula={"=ROUNDDOWN(127,-1)"}
  grid={{}}
  expected={"120"}
/>

<FunctionExample
  title={"Select zero decimal places to return an integer."}
  formula={"=ROUNDDOWN(12.345,0)"}
  grid={{}}
  expected={"12"}
/>

<FunctionExample
  title={"The number cannot be read from nonnumeric text."}
  formula={"=ROUNDDOWN(\"invalid\",2)"}
  grid={{}}
  expected={"#VALUE!"}
/>

<FunctionExample
  title={"Trim decimals without rounding up"}
  formula={"=ROUNDDOWN(3.14159,3)"}
  grid={{}}
  expected={"3.141"}
/>

<FunctionExample
  title={"Round down a negative value at the hundreds place"}
  formula={"=ROUNDDOWN(-987.65,-2)"}
  grid={{}}
  expected={"-900"}
/>

## FAQ

### Does ROUNDDOWN always move toward negative infinity?
No. It moves toward zero, which is different from FLOOR-style behavior on negatives.

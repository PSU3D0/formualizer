Returns the smallest value in a database field for records matching criteria.

`DMIN` applies criteria filtering and then evaluates the minimum numeric value from `field`.

The Formualizer engine in this repository at 0.15.0 plus unreleased changes computes the example results. Known differences from Excel are listed on this page.

## Syntax

`=DMIN(database, field, criteria)`

## Arguments

| Argument | Type | Required | Default |
| --- | --- | --- | --- |
| `database` | any | Required | — |
| `field` | any | Required | — |
| `criteria` | any | Required | — |

## Remarks
 - An equality criterion for a date or number (`"10/26/1999"`, `"36459"`, `36459`) also
   matches text cells holding that date; `&lt;&gt;` and ordering criteria do not read date text.
 - Criteria rows are ORed together; criteria columns on the same row are ANDed.
 - `field` resolves from a case-insensitive header label or 1-based index, and invalid resolution yields `#VALUE!`.
 - If no numeric values are matched, this implementation returns `0`.

## FAQ

### How are mixed criteria (text plus numeric operators) handled in DMIN?
Criteria are parsed per criteria cell, then applied as AND within row and OR across rows before the minimum is chosen.

Returns the numeric code for a specific error value.

The Formualizer engine in this repository at 0.15.0 plus unreleased changes computes the example results. Known differences from Excel are listed on this page.

## Syntax

`=ERROR.TYPE(error_val)`

## Arguments

| Argument | Type | Required | Default |
| --- | --- | --- | --- |
| `error_val` | any | Required | — |

## Return type

Number

## Remarks
 - Standard mappings include: `#NULL!`=1, `#DIV/0!`=2, `#VALUE!`=3, `#REF!`=4, `#NAME?`=5, `#NUM!`=6, `#N/A`=7.
 - Additional internal error kinds may map to extended non-standard codes.

## Error cases

 - Non-error inputs return `#N/A`.

## Examples

<FunctionExample
  title={"Identify the error code produced by division by zero."}
  formula={"=ERROR.TYPE(1/0)"}
  grid={{}}
  expected={"2"}
/>

<FunctionExample
  title={"Identify the code for a missing value instead."}
  formula={"=ERROR.TYPE(NA())"}
  grid={{}}
  expected={"7"}
/>

<FunctionExample
  title={"Identify a numeric domain error at the square-root boundary."}
  formula={"=ERROR.TYPE(SQRT(-1))"}
  grid={{}}
  expected={"6"}
/>

<FunctionExample
  title={"A number has no spreadsheet error code."}
  formula={"=ERROR.TYPE(0)"}
  grid={{}}
  expected={"#N/A"}
/>

<FunctionExample
  title={"Non-error input returns N/A"}
  formula={"=ERROR.TYPE(10)"}
  grid={{}}
  expected={"#N/A"}
/>

## FAQ

### What if the input is not an error value?
ERROR.TYPE returns #N/A when the input is not an error.

# Indexed imported target preparation

Calamine deferred packages support target isolation across ordinary formulas, complete shared families, and validated fragmented shared families. A target demands the final source-order formula at each coordinate in its dependency closure, not every dependency of the sheet package or shared template family. Shared anchor text is reconstruction evidence; the anchor cell's dependencies are demanded only when the closure reaches that cell. Existing preparation errors remain exceptions, not cell errors or catch-and-skip events.

## Source and authority contract

- Indexed replay returns every matching source record, with unique source-order tokens and shared ownership. The engine checks coordinate coverage and final-record agreement with compressed ownership before parsing the winning record. Ordinary exceptions and later ordinary overrides retain their own formulas.
- Calamine retains complete coordinate geometry and lazily builds text-free coordinate/offset and shared-index/anchor-offset locators. Descendants use the most recent preceding anchor, or the first subsequent anchor for forward descendants. Repeated requests seek only matching records and required anchors; arbitrary source inspection still uses its existing replay lookup.
- Completely demanded eligible families use the existing compressed placement preparation and prevalidated plane append, before descendant replay or per-member AST/dependency expansion. This is a family selection, not package-wide widening. Residual partitions can also be selected completely, with only their demanded ordinary/shared legacy exceptions replayed. If a late plane append rejects the candidate, indexed exact fallback is obtained lazily and validated before legacy preparation.
- Already queued source regions are coalesced by indexed coordinates, and partial shared expansion waits until known ordinary/name dependency discovery has finished. Thus a narrow range followed by an ordinary `SUM` that demands the complete family does not first retain thousands of orphan member ASTs. Complete selections remove only their own source-family metadata; mixed partial selections preserve residual authority.
- Partial targets commit selected cells through the existing legacy graph transaction. Before publication, complete families touched by partial selection are converted into validated residual partitions; existing partitions are split by exact selected coordinates. Original source identity, source order, template origin/text, reconciliation counts, and ordinary-exception kinds are retained. Consumed members become explicit legacy exclusions, never fabricated holes.
- A private engine-identity-bound consumed-member proof is published only after source generation, revision, admission, graph and plane validation. Suppression alone cannot establish this proof. Residual fragment ownership rejects suppressed fragment cells and unproven suppressed legacy cells. Full preparation omits only proven consumed members from its exact legacy replay set. Final transaction validation checks engine identity again.
- Residual legacy fallback reconciles replayed members **plus** proven consumed legacy members against original exact counts. Replaying a consumed coordinate, omitting another member, mismatching ownership, or supplying duplicate coordinates is rejected. Cross-fragment dependence retains the existing fallback: for example, shared `Bn=B(n+500)+1` already requires legacy preparation on a full-only baseline, and partial consumption does not newly refuse that valid workbook.
- Selected master/member edits or deletion keep their exclusions. The imported template remains immutable reconstruction evidence for remaining cells; full replay cannot overwrite those edits. Editing an unconsumed family member retains the pre-existing conservative invalidation policy.
- Residual metadata, suppression/proof capacity, and scratch/work are admitted before publication. A request exceeding 128 residual fragments or 4,096 explicit legacy exclusions per residual family fails before consuming source; full preparation remains available. Fully consumed direct domains need no residual fragment proof.

## Cost and accounting

One target does not expand an entire shared family into ASTs or graph vertices. Eligible residual domains and untouched families remain compressed during later full preparation. Residual preparation does perform a full bounded source replay for reconciliation; it is not claimed to have the full-only direct path's constant cost.

Initial locator construction is O(N log N); repeated selected reads are O(K log N + matching records/anchor reads). A shared descendant takes one record and one anchor decode. The engine additionally walks/clones compact family metadata while validating and preparing residual geometry; this is not a per-target spool scan, but many-family packages are not claimed to have constant metadata cost. No extra graph, workbook snapshot, retained text lane, or unconditional AST cloning is introduced.

Complete shared coordinates now remain in the package's coordinate vector and staged point index. The vector adds 8 bytes per unique shared coordinate, plus existing point-index node overhead; the locator itself remains lazy. Independent allocator instrumentation of a 10,000-member fixture measured an additional 182,192 live requested heap bytes (about 18.22 bytes/member) for this cold coordinate/index storage. That is not RSS, allocator usable capacity, or peak memory; the storage design is unchanged by complete-family demand optimization. A 10,003-record shared microprobe retains 262,400 locator bytes (coordinate and anchor capacities), with 300 bounded work units for 100 subsequent descendant reads. These buffers use the optional replay cache footprint token: actual resident capacities are retained-admitted, survive failed preparation accounting, and are re-admitted on warm requests. This is not a general RSS accounting claim for all source metadata.

Immutable spool load totals are reported once. Selected cell/family counts describe the demand; remaining staged counts and source visibility describe residual ownership. Compressed ingest reports continue to describe original family reconciliation, while actual graph and span counters describe publication work.

## Compatibility boundaries

The hidden replay trait adds default-compatible `replay_selected_exact`; producers opt into complete shared coordinate coverage with `with_complete_coordinate_coverage`. Existing partition constructors and their required fields do not change. Public API snapshots and release notes are maintained separately.

Backends without indexed exact replay, incomplete geometry, ordinary-before-package reconciliation, and existing authoritative/unknown-sheet compatibility cases retain conservative preparation. Unsupported metadata or missing shared anchor evidence can require conservative replay under the existing importer policy. This does not expand support for generic explicit-member family transports; producers must not opt into unsupported residual authority shapes. No table-ingestion, partition-execution product, error-policy, or binding behavior is added here.
